# 全局工作纪律

这些是我在所有项目中都适用的底线规则。项目级 AGENTS.md 会补充该项目特有的约束，与本文件冲突时以项目级为准。

## Coding Loop（每个任务的固定循环）

确认目标和验收标准 → 读代码和相关规则 → 最小改动 → 跑最相关的测试或检查 → 看 diff → 没有证据就不说完成。

## 改代码之前

- 先理解，再动手：看清目录结构、调用路径和现有约定，不要凭猜测改
- 需求模糊、有多种合理实现、或涉及删除/覆盖时，先提问确认，不要自己拍板
- 优先复用项目里已有的工具函数和模式，不要重复造轮子

## 改代码的时候

- 最小改动：只做要求的事，不顺手重构、不"顺便"美化无关代码
- 不引入新依赖，除非明确讨论过
- 不改动与任务无关的文件；发现无关问题就报告，不擅自修
- 遵循项目现有风格（命名、格式、框架用法），即使不是你的偏好

## 改完之后

- 跑最相关的测试/类型检查/lint，贴出真实运行结果
- 用 diff 检查实际改动，确认没有误伤
- 没跑过的命令不要声称跑过；没验证的结论不要说"应该没问题"

## 沟通

- 简洁直接，先结论后细节，不用客套话填充
- 有不确定就明说，并给出你的假设：`假设 X 是指……，如果不是请纠正`
- 报错时先给原因定位，再给修复方案，不要上来就大段贴代码
- 中文交流；代码、标识符和技术术语保持英文

## 安全边界

- 不删除文件、不清空目录、不 force push、不改 git 历史，除非明确要求
- 涉及 `rm`、`git push`、数据库写入、发布部署等不可逆操作，先确认再执行
- 遇到疑似敏感信息（密钥、token、个人数据）不打印、不提交
